# CMU path libraries

`startPaths.ply`, `pathList.ply`, and `paths.ply` are the shared CMU candidate
paths generated by `path_generator.m`. Runtime uses a robot-specific directory:

| Robot | Collision search radius | Runtime directory |
| --- | ---: | --- |
| Unitree Go2 | 0.55 m | `go2/` |
| DOSO Thunder V4 | 0.75 m | `thunder/` |

The Go2 value follows the CMU Go2 path generator. Its `0.55 m` radius is about
`0.17 m` larger than the Go2 launch footprint half-diagonal. Thunder keeps the
same tracking allowance: `hypot(0.50, 0.30) + 0.17 = 0.752 m`, rounded to
`0.75 m`. This is the CMU collision-library allowance. The runtime CMU backend
also validates the exact selected group path with the configured rectangular
footprint; the endpoint does not sweep the planned path a second time.

Regenerate both runtime libraries from this directory with:

```powershell
python generate_library.py
```

The generator copies the shared PLY files and writes each profile's
`correspondences.txt` and `search_radius.txt`. MATLAB and SciPy are generation
tools only. At startup the native backend requires both files, validates the
radius, and uses that exact value for the runtime correspondence-grid warp.
The correspondence table and its radius therefore cannot be mixed across
profiles.
