# 已知限制与下一步

当前版本已经完成车辆违停检测研究闭环验证：

```text
板端摄像头取流
HBM 车辆检测
ROI 标注和记忆
场景关键帧匹配
车辆进入禁停区停留后报警
断网本地保存报警
巡检结束拉回记录
```

但当前 ROI 机制仍属于验证方案，不建议直接作为最终生产方案。当前包也尚未接入 LingTu 主系统的 `TrustedParkingObservation` / `InspectionEvidenceStore` 合同，因此报警只能视为研究候选证据。

## 当前 ROI 风险

当前逻辑是：

```text
当前画面匹配某个关键帧
加载该关键帧绑定的 ROI
车辆进入 ROI 后开始计时
```

风险：

```text
环境光变化会影响场景匹配
镜头角度变化会导致 ROI 位置偏移
运动模糊和遮挡会导致 ROI 不出现
场景误匹配可能把 ROI 加载到错误画面
固定像素 ROI 不会随透视变化自动变形
```

为缓解这些问题，当前包内已经做了：

```text
一个 ROI 支持多个关键帧特征
场景匹配阈值降到 0.6
匹配成功后 ROI 保持 5 秒
报警要求车辆置信度 >= 0.15 且持续超过 2 秒
```

这些只能缓解，不是根治。

## 建议下一步

更可靠的落地方案是升级为：

```text
场景候选匹配 + 特征点几何验证 + ROI 单应性投影
```

即：

```text
画 ROI 时保存关键帧、ROI 多边形、稳定特征点
巡检时先匹配候选关键帧
再用特征点匹配和 RANSAC 计算单应性矩阵 H
把关键帧里的 ROI 投影到当前画面
只有几何验证通过才启用 ROI
```

需要增加的验证条件：

```text
匹配内点数量达到阈值
内点比例达到阈值
重投影误差足够小
投影后的 ROI 面积变化合理
投影 ROI 在画面内
连续多帧几何验证通过才开始计时
几何验证失败时不显示 ROI，不报警
```

这样可以明显降低：

```text
ROI 加载错场景
ROI 位置偏移
误报警
漏报警
```

如果现场允许贴标记，另一种更稳的方案是使用 AprilTag/ArUco 标记：

```text
每个禁停区绑定唯一 marker id
摄像头看到 marker 后确定禁停区
根据 marker 姿态投影 ROI
```

这是比自然场景匹配更稳定的工程方案，但需要现场允许布设标记。

## 产品化准入条件

进入 LingTu 主线前至少需要：

```text
trusted observation 合同适配
正常/违停/未知/仅采集/需复核状态映射
Gateway + Inspection Workbench e2e 测试
摄像头断流、模型不可用、ROI 未匹配、低置信度的 fail-closed 行为
实机断网和进程重启后的结果一致性验证
```
