| Family | What the guide establishes | LingTu disposition |
| --- | --- | --- |

| GPS | Configurable origin and mounting; position/navigation output | First experimental LingTu measurement/endpoint slice implemented below |
| Infrared | Compressed-image camera option | Not accepted as proof of radiometric temperature; thermal integration remains pending |
| Semantic camera | Class-ID image output | Useful later for inspection annotations, not a replacement for temperature or detection confidence |
| PTZ, fisheye, panorama RGB | Camera projection/control variants | Later expansion; not silently counted as implemented in LingTu |
| Airy / generic LiDAR | Additional scan families | Later expansion; retain each scan pattern's field/time semantics |
| Acoustic | Not listed in the inspected public sensor guide/templates | No supported microphone/pressure contract established; do not claim whole-binary absence |

The upstream's template rates are requests, not measured delivery rates. Its
initial robot sensor dictionary is empty; merely possessing templates does not
activate streams. We preserve the same distinction between a plan, a bound

## Implemented: experimental GNSS measurement and SensorRuntime seam

Code: `sim/runtime/sensors/gnss.py`; tests:
`tests/sim/test_gnss_sensor_runtime.py`.

- [x] Explicit WGS84 ellipsoidal map origin; no hard-coded city or fake survey.
- [x] Map translation/yaw, body orientation and antenna lever arm → ENU → ECEF
  → latitude/longitude/ellipsoidal altitude, in degrees/metres.
- [x] Existing `runtime.msgs.gnss.GnssFix` carried in the existing stamped sensor
  envelope. No new wire schema or Python DDS mirror.
- [x] Exact session, model/reset generation, deadline and source-body matching;
  no wall-clock timestamp or finite-difference truth replacement.
- [x] `set_noise_enabled(bool)`: independent horizontal/vertical Gaussian error,
  explicit seed, deterministic draws per sample identity. Physics remains unchanged.
- [x] Covariance rotated into ENU at the measured fix, not assumed identical to
  the map-origin frame over arbitrary distances.
- [x] `set_fix_available(bool)`: scenario-controlled outage/recovery, not a
  constellation or occlusion solver. Default **NO_FIX** with invalid coordinates;
  no last-known truth leak. Valid experimental measurements use **SIMULATION**,
  never RTK_FIXED, and do not invent satellites.
- [x] Optional `gnss` configuration is consumed by `SensorRuntime.from_plan`.
  `GnssEndpointFactory` matches only the explicit GNSS route and requires either
  a native executable or an explicit test sink, never an implicit fake sink.
  Production composition adds the endpoint only when `gnss_publisher` is supplied.
- [x] Effective configuration and fix quality recorded as **EXPERIMENTAL**.
  Evidence rejects a changed origin/mount/noise calibration; only explicit
  outage and noise-enable toggles may differ from the plan.

The initial measurement-only pass did not include Catalog or native DDS. The

An explicit perfect/no-noise sample must not be called an RTK measurement.

## Follow-up: REA/Ghidra pseudocode and native GNSS delivery

The same verified ELF projection was opened with three explicit function seeds.
`rea-seeded-plan.json` and `sensor-seeds.tsv` preserve the selected addresses.
`rea-seeded-run/01-batch_decompile.json` contains **3/3 successful pseudocode
results** from Ghidra 12.1.4. This is bounded recovery, not a whole-program decompile:

- `EmitGps`: local UE centimetres are scaled by 0.01, a Y-axis sign is changed,
  and reference-relative coordinates are converted using radius 6378137 and a
  latitude cosine clamped to at least 0.01. Heading/speed and seconds/nanoseconds
  are present. Its pseudocode has a bad-instruction/control-flow truncation at
  the publishing tail; the preceding raw disassembly supplies the publishing-call
  evidence. This is not proof that every MATRiX GPS implementation is identical.
- `ApplyInfraredPostProcess`: selects a material for the infrared camera mode,
  removes the prior material and updates/inserts a blend entry with weight clamped
  to 0..1. No raw temperature contract is established by this function. Material
  internals and possible other thermal paths remain unexamined.
- `AddVirtualGps`: validates/configures the sensor and updates worker virtual
  sensors. Registration alone does not establish a valid GNSS measurement.
