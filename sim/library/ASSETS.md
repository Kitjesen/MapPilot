## 每件的交付内容

1. 完整材质与独立视觉部件，米制尺寸、命名、局部坐标、转轴明确。
2. MJCF 物理描述：固定/自由本体、质量、惯量、简化碰撞体、摩擦、关节和限位。
3. 动作接口：驱动、制动、转向、开合或转动，声明单位和输入范围。
4. UE VisualPlan 的部件到 MuJoCo 稳定 Body ID 绑定。
5. 同次运行证据：静置、受力/接触、部件运动、限位、停止、Reset 与 UE 同步。

未取得实测资料时，质量、摩擦和驱动力只能标为**仿真设计假设**，不能称为已标定的真实产品参数。

## 运行边界

- MuJoCo 是质量、惯量、关节、接触、速度与位姿的唯一计算方。
- UE 负责显示；鼠标命中/操作按钮产生有范围的动作意图，不能直接覆盖物体位姿。
- UE 的物理碰撞必须保持与现有架构一致；不得让 Chaos 与 MuJoCo 同时积分同一道具。
- 固定设备应保持固定，只允许它的活动部件运动。不是所有物体都加 freejoint。
- 本地物理试验场只证明模型能否工作，不等于生产 Runtime 或 UE 验收通过。

## 已确认的接线缺口

当前世界视觉投影主要实例化静态 box/cylinder；世界道具没有通用的活动 Body 绑定。
`ALingTuSimWorldEntityActor` 与 `AttachWorldEntityVisual` 仅应用初始位姿。
现有 `ULingTuSimBodyBindingComponent` 可以复用，但还需补充道具声明、导入、绑定数量与 readiness 合同。
不通过把道具伪装成 RobotPackage 或新建第二套位姿权威来绕开此问题。

下一步接线的最小路径：

1. 复用已有的、与机器人类型无关的 `ALingTuSimBodyActor` 和 `ULingTuSimBodyBindingComponent`。
2. 给世界视觉投影明确增加活动 Body ID 与局部视觉偏置；校验所引用的真实 MJCF Body 存在。
3. 将活动道具纳入完整帧、绑定计数、Reset 和卸载事务，不改机器人主控制合同。
4. 把操作意图送到 MuJoCo 关节驱动，而不是播放预览动画；UE 保持呈现与命中选择职责。
5. 先用道闸/门完成同次 UE + MuJoCo 的受力、限位、碰撞、停止及重置证据，再批量对齐七件 Tripo 资产。

本轮没有修改 UE C++、运行 UE、生成新的 WorldPackage 或通过上述接线验收。
