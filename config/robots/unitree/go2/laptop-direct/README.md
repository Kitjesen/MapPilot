# Windows 笔记本直连 Go2

LingTu 已安装在 NX，笔记本只需要浏览器和以太网，不需要安装 LingTu、Python、ROS 或复制 SSH 密钥。

2026-09-15 已在 `DESKTOP-17EDVN1`（Dz）完成配置并通过 HTTP 验证：
“以太网 2”使用 `192.168.123.100/24`，直连 NX `5050`，没有默认网关。
浏览器原有独立 Clash 代理 `127.0.0.1:7898` 保留；用户 CLI 代理从
`thunder.lan:7890` 改为本机 `7898`，系统 CLI 原有无监听的 `7897` 同步纠正，
WinHTTP 从开发电脑代理恢复为直连，NO_PROXY 增加 NX 地址。
更新后已验证本机代理 HTTPS 返回 204、NX navigation/status 返回有效 JSON。
旧程序需重新启动才会采用新的环境变量。尚未做禁用 Wi-Fi 或重启后的现场测试。
此次配置只针对这台笔记本；`repair-dz-proxy.ps1` 不应在其他电脑运行。
备份在笔记本 `%LOCALAPPDATA%\LingTu\network-before-20260915-134811.json`，
网卡原配置记录在同目录 `ethernet-before.json`。

## 换线

1. 先让机器人停稳，结束当前运动操作，松开所有遥控按键。
2. 拔掉 Sunrise 连接机器狗对外网络口的线，改接笔记本。保留机器人内部 NX、主控、雷达的网络连接和供电。
3. 笔记本按 Win+R，输入 `ncpa.cpl`，找到实际接线的以太网适配器。
4. 打开属性 → Internet 协议版本 4，设置以下参数：

| 参数 | 值 |
| --- | --- |
| IP 地址 | `192.168.123.100`（须未被其他设备占用） |
| 子网掩码 | `255.255.255.0` |
| 默认网关 | 留空 |
| DNS | 留空 |

不要修改 NX 的 `.18` 地址；不要使用雷达 `.20`、Sunrise `.99`、主控 `.161`。

5. 双击 `Go2-Control.url`，或在浏览器输入 `http://192.168.123.18:5050/`。
   `Go2-Observe.url` 是只读页。快捷方式只打开页面，不发送运动命令、不切换模式。

无法连接时，在 PowerShell 执行：

```powershell
Test-NetConnection 192.168.123.18 -Port 5050
```

`TcpTestSucceeded: True` 说明网页端口可达。若为 False，先检查实际以太网地址、网线和机器人供电。
原开发电脑的 `127.0.0.1:15050` 不能直接用于这台笔记本。

## 离线使用与当前入口（2026-09-17 更新）

```text
Windows 笔记本的浏览器 ── 网线 ── NX：网页、建图、控制与地图存储
```

这条链路不经过开发电脑、Sunrise、互联网或 Tailscale。浏览器页面和数据由 NX
提供；机器人模型等静态资源也在 NX。不要在随行电脑使用开发电脑上的
`127.0.0.1:15050` 或 `127.0.0.1:15052`。Windows 显示“无 Internet”不代表网线
局域网断开。若使用代理/VPN，须让 `192.168.123.18` 直连。

截至 2026-09-17，NX 已安装 `.32` 和后续点云显示补丁。这个记录不代表当前设备
在线，也不代表断开 Wi-Fi、重启后的整套流程已经验收。

1. 打开 `http://192.168.123.18:5050/`，确认页面已连接、雷达与位姿持续更新。
   控制页面不要带 `?observe=1`；该参数是只读监控，不能遥控或保存。
2. 页面处于“建图”时，顶部点击“遥控”，随后点击场景让键盘聚焦。
   W/S 前后、A/D 侧移、Q/E 转向；松键停车，Space 停止，Esc 退出遥控。
   限速可选择 0.50 m/s；Shift 为当前限速的 40% 精细模式。
   建图是直接遥控，需要操作者主动绕开障碍，不提供规划绕障。
3. “视图 → 累计建图”查看本次关键帧累计点云，“全图”调整视野到数据范围。
   局部地图只反映当前窗口，当前扫描是实时回波。累计图是采样预览，不是完整
   原始数据，也不代表所有显示区域已经可以导航。当前历史残影清理仍待修复。

初次离线验收时，先让机器人保持静止，在笔记本关闭 Wi-Fi 后重新加载 NX 页面，
检查点云与位姿仍更新，再在现场空旷处短按遥控、松键确认停车。这能发现代理、
页面资源或实际链路仍依赖无线网络的问题；仅加载已缓存页面不算通过。

公网断开不影响上述有线链路；网线断开会同时失去网页和网络遥控。
原开发电脑可能无法继续远程协助，但不应成为随行电脑工作的依赖。

## 开机后没有建图页面

不能把 NX 开机等同于建图 Product 已启动。先检查网页端口；如果端口不通但 SSH
可达，在随行电脑 PowerShell 运行：

```powershell
ssh unitree@192.168.123.18
```

在 NX 上使用已经安装的机器配置及 ProductControl：

```bash
sudo -i
set -a
source /opt/lingtu/config/go2-native.env
set +a
bash /opt/lingtu/current/scripts/lingtu --robot unitree/go2 --env real status --json
# Only start a new mapping Product after any existing map has been saved.
bash /opt/lingtu/current/scripts/lingtu --robot unitree/go2 --env real switch map
```

若已经处于建图且数据正常，不要重复切换或重启。启动失败时保留错误信息，
不要通过逐个启动 systemd 服务绕过 ProductControl。上述启动不发送运动方向。

## 建图结束：保存与备份

1. 遥控回到便于核对的位置，松键停稳，退出遥控。回到起点有助于检查接缝，
   但回到起点不等于系统已经成功闭环。
2. 顶部点击“保存地图”，输入新的地图名，例如 `building_1f_20260917`。
3. 等待“已保存”。后端会写入地图、清理动态点并生成地图产物；
   “保存中”或按钮已经点击都不算完成。保持 NX 供电，不在保存期间切换 Product。
4. 打开“已存地图”，选择刚才的名字查看整图；保存详情显示实际存储位置。
   默认路径为 NX 的 `/var/lib/lingtu/maps/<地图名>/`，不是笔记本磁盘。
   保存成功也不等于定位、通行判断与导航已经验收。

如果显示超时或断线，先恢复连接、刷新地图库并确认后台结果；不要立即关机或
反复用相同名字保存。当前网页等待保存结果最长约 3 分钟，超时不一定代表后台已停止。

地图保存成功后，可以通过同一根网线备份整个地图目录。在 Windows PowerShell：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\Documents\LingTuMaps" | Out-Null
scp -r unitree@192.168.123.18:/var/lib/lingtu/maps/building_1f_20260917 "$env:USERPROFILE\Documents\LingTuMaps\"
```

将示例地图名替换为实际名称。复制整个目录，保留点云、地图产物及元数据；
不要仅备份网页截图。原始传感器录制是另一项操作，不等于保存地图。

建图结束必须确认保存成功，再关机。需要恢复原调试通路时，机器人停稳后接回 Sunrise。
笔记本以后用于普通有线网络时，把此适配器 IPv4 恢复为原设置（通常为自动获取）。
