# 支撑不连通时停止无效朝向搜索

日期：2026-10-25。范围：原生 OctoPlanner3D 的 heading 搜索；无新依赖、无地图
服务或产品启停变更，不改变机体模型、余量、未知空间、支撑、坡度或步高条件。

## 原因

原搜索已缓存XYZ支撑位置和支撑边，但是状态仍为XYZ+yaw。局部拒绝断口上的边，
不等于知道起点所在支撑区域无法到达目标。直线距离启发式仍会让断口前的候选
显得接近目标，导致大量合法但无法到达目标的朝向和机体扫掠查询，最终10秒截止。
基础支撑拒绝发生在BodyQuery之前，不能用BodyQuery的reject_support计数推断
全局没有检查支撑。

## 本轮修改

1. 将位置支撑、移动边支撑检查放到机体姿态检查之前。已缓存失败的连接直接跳过。
2. 进入完整朝向搜索时，先用相同XYZ网格进行一次不含机体朝向约束的基础支撑搜索。
   仍保留Z与不同高度表面，直接调用现有poseSupportFree、supportConnectionFree。
3. 只有可达支撑图被穷尽，且无法连接目标时，返回support_disconnected。有支撑
   通路不等于机体能通过，仍须原有yaw、机体及连续扫掠检查。
4. 复用现有support_allowed/support_edges，每次请求结束即释放；不保存跨任务
   区域记录。预检最多用剩余迭代预算的一半，已用展开计入原总预算，不新增产品参数。
   预检未穷尽时继续原搜索，不能声称无路；取消仍返回cancelled。

判定成立的范围是当前搜索的离散三维位置/连接规则，而非任意连续路径、跳跃或
其他步态。朝向搜索的每条平移边都必须通过同一基础支撑规则，因此忽略yaw和
机体碰撞后的图是一个放宽约束的图，穷尽它不会误删原算法能找到的路线。
预检使用相同的精确目标连接与容差终点语义；无支撑或未知不是二维投影后的空白。

外接圆引导失败依然不能作为无路判据，因为它可能过于保守。当前顺序保留直接
候选和既有引导，再进入上述预检和完整朝向搜索。

## 对照结果

Windows Release，同一七场景、两种模型、前后各三轮，共84次规划。每轮独立
session先准备地图再计时，模型交替运行，无并行编译。桌面负载未隔离，不把
毫秒差异解释成目标板实时保证。所有路径和成功/失败状态一致，断口的失败原因
由截止取消变为support_disconnected。

| 场景/模型 | 前中位 ms | 后中位 ms | 结果 |
|---|---:|---:|---|
| 支撑断口 / 单OBB | 10007.94 | 788.43 | 由截止转为明确不连通 |
| 支撑断口 / 34部件 | 10008.38 | 675.11 | 由截止转为明确不连通 |
| 对齐门洞 / 单OBB | 32.07 | 30.01 | 都成功 |
| 对齐门洞 / 34部件 | 26.55 | 27.09 | 都成功 |
| L形通道 / 单OBB | 92.97 | 116.16 | 都拒绝；预检有额外工作，不宣称普遍提速 |
| L形通道 / 34部件 | 614.31 | 591.92 | 都成功 |

断口预检穷尽12840个XYZ状态，BodyQuery只检查起点和目标两次、边查询0次。
一次记录中预检约265 ms；整次仍约0.8秒，包含前面的既有引导等工作。因此当前
没有达到所有困难场景几十毫秒，也没有解决所有姿态搜索慢的问题。

## 回归与证据

heading_smoke新增或加强：完整支撑断口只查起终点机体；预算不足回退且不超总预算；
预检取消；直线断口旁有桥仍可绕行；同XY上下楼层不连通；阻挡原目标时仍接受合法
容差终点。原有窄门朝向、转动中间碰撞、非格点目标、未知起点、Z变化和取消回归
继续通过。body_query_smoke通过，保留实际机体与支撑断口检查。正式目标运行时
已有failure_reason透传，不新增另一套错误通道。
