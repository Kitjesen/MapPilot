# 三维表面通道预构图（2026-10-31）

[后续同图复测](surface-graph-costs-20261031.md)对齐了 DimOS 与灵途的计时范围，并报告了进一步缩短准备耗时、改善两条绕行路线的结果。下文保留第一版数据。

本轮已在既有 OctoMap 与三维通行规则之上，把可复用的表面连接及通道代价移到地图准备阶段。五个真实地图请求各重复三次，修改前后均为15/15，修改后全部使用稀疏通道图，最长跨度不再回退完整XYZ搜索。查询显著加快，但一次准备成本增加，两条路线约长10%；尚未达到DimOS的整体性能，也不证明实机执行。

- DimOS MLS：`26144f7fd8424bdc33ab97dcd58e9497f2d413ee`，Apache-2.0。参考[节点通道构建](https://github.com/dimensionalOS/dimos/blob/26144f7fd8424bdc33ab97dcd58e9497f2d413ee/dimos/navigation/global_planner/mls_planner/rust/src/edges.rs)、[查询及后处理](https://github.com/dimensionalOS/dimos/blob/26144f7fd8424bdc33ab97dcd58e9497f2d413ee/dimos/navigation/global_planner/mls_planner/rust/src/planner.rs)。

原版 OctoPlanner 的 v6 完整图记录在 240 秒观察内尚未进入第一个目标查询；共同裁图初始化约114秒，但随后五个请求在约10–800毫秒内失败。因此不能概括为“官方所有查询都很慢”，也不能把快速失败当成成功路线性能。源码的派生层准备遍历整个三维包围盒；原版严格正下方一格支撑且无补面，与本轮支持合同不同。证据索引在 `build/surface-graph-20261031/validation/README.md`。

## 当前集成边界

`SurfaceIndex` 保留同一 XY 的多个高度表面；`SurfaceGraph` 在地图准备期间建立静态三维邻接、边界距离偏好、稀疏节点和节点间实际细格通道。目标查询复用这些通道，并在当前请求中检查实测占据/自由证据及显式禁区。直接端点连接失败后，局部 XYZ 连接复用已有吸附半径；仍不能连接时，原 XYZ 搜索继续承担回退。

同一地图身份和配置复用准备结果，地图或配置变化后重建。临时 overlay 和当前观测按请求校验，不重建静态图、不永久删除图边。构图可以取消，未完成的图不作为可用准备结果发布。没有新增独立 yaw 搜索或公共模式。

这是对 DimOS 工作流的适配，几何与代价仍采用灵途已有三维查询；不是完整移植其精确墙距场、代价模型或弹性带墙距梯度力。

## 后处理已发现并修正的正确性问题

1. 长平台后接20厘米台阶时，若只看端点连接有效，长距离拉直会把整段平台改成缓坡。Executor 3.5米预瞄随后插出过高的参考高度，使低平台上的地面退出局部参考带。现在只在等高片段做长拉直和弹性移动，保留原升降边及两端位置；非等高边不重新插点。8米平台回归保留4.7米低平台端点和5.1米高平台端点，3.5米预瞄及4米位置仍保持低平台参考高度。
2. 图的名义机身高度与实际测量首尾高度可能略有差异，不能把这种偏差永久保留成台阶。首尾等高且完整直连查询有效时，直接保留测量端点之间的路线；此常高查询不会使用升降边的支撑放宽。新增首尾Z=-0.01、内部名义Z=0.025回归。
3. 原台阶边有效并不保证每个线性插点子边有效。新增点先投影到对应表面，再检查全部新子边；任一子边不通过或长度增加时保留原边。端点固定，取消不返回半条路线。

独立 smoothing smoke 已覆盖墙、相同XY不同高度、台阶插点、长平台预瞄、测量高度、长度、端点和取消。修改前失败与修改后记录在 `build/surface-graph-20261031/validation/platform-before.log`、`platform-after.log`、`measured-flat-before.log`、`measured-flat-after.log`。正式模块重新链接后，8个相关CTest全部通过。

最长跨度的初版图查询仍回退XYZ。诊断发现起点附近64次直接接图尝试全部失败，并不是全图没有连接。原始起点需要先保持高度平移，再接上名义表面。增加复用已有吸附半径的局部XYZ连接后，固定请求只扩展3次，保留原始起点并成功接图。这个连接不跳过任何实际边的三维检查。

## 同条件实测

输入是本机已有的 `903room_v6_corridor`，975,380个占据格、12,908,495个树节点，5厘米分辨率。它不是尚未取回的NX上10月29日新地图。使用完全相同的原始五组端点、地图、20厘米补面、半径0.25米圆柱、机身上下范围0.10/0.25米、支撑0.35±0.05米、步高/坡度、12秒查询期限。基线是已修好起点的原XYZ实现，不是此前起点被拒绝的版本。C++ Release、WSL Linux、单进程顺序运行，地图准备不计入目标查询。

|走廊转角|14.5 m|919 ms|16 ms|15.35 → 15.03 m|
|房间到走廊|17.9 m|4,634 ms|156 ms|28.59 → 31.59 m|

五组各3/3成功，每组重复输出路线完全相同，首点保持原始起点，终点在原有15厘米容差内。15次新查询全部走稀疏图，XYZ回退0次。新查询实际范围13–576毫秒。主机负载变化明显：旧最长查询范围6.73–11.07秒、新最长0.24–0.46秒；这里是这台电脑本轮测量，不能据此承诺NX固定倍数或固定延迟。墙钟和CPU逐次数据保留在JSONL中。

一次性总准备：旧14.70秒，新62.28秒；新表面索引2.90秒，通道图构建44.95秒，其余包括读OctoMap及已有准备。图有5,939节点、1,092条无向通道；其中含大量独立表面小分量，不能将所有节点视为连通走廊。当前同一PlannerSession、地图与配置内复用，进程重启仍须重建，没有增加磁盘图缓存或新格式。

新查询阶段日志把工作分开：通道搜索与当前几何复核约7–44毫秒，平滑约4–538毫秒。下一步优化依据是准备阶段大量静态几何检查，以及后处理的反复几何查询；当前证据不支持继续把主要耗时归咎于稀疏Dijkstra。稀疏图和软代价不保证相对原XYZ的最短路，因此两条路线约长10.5%需要保留为质量差异，不能宣称所有路线都更好。

- 重新编译模块，8个相关CTest通过：prepared_surface、surface_graph、route_smoothing、start_evidence、xyz、neighborhood、grid、no_air_climb。包含实测障碍优先、障碍移除后下一次请求可用、地图/配置缓存、取消不发布半图、重复请求不泄漏旧结果、分层/台阶/断崖/墙等。
