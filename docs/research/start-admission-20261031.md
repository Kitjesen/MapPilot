# 起点接入修复与算法对照（2026-10-31）

本轮只改统一全局入口的旧占据处理：当前请求初始机身包络相交的旧静态体素不再要求自由观测才能豁免。当前真实命中仍优先，初始范围外的障碍、显式禁区和地面支撑不改变；原始地图不写回。初次目标、重规划、预览和离线调用共用入口。豁免粒度为相交的整个体素，并非精确几何裁切。

`input/map.cpp` 去除初始机身的重复推断，只提供实测空闲与占据回调。普通 body-centre 模式已覆盖；`lowest_traversable_only` 预构图已经移除的候选不会由这个回调重建，本轮未扩改该既有模式。

## 与 DimOS 的结构差距

- 固定 DimOS `26144f7fd8424bdc33ab97dcd58e9497f2d413ee`：先提取多层表面、邻接、墙距，构建稀疏节点及通道，查询时在节点图上 Dijkstra，再用局部细格接入起终点。每个 XY 可有多个高度层。
- 当前灵途：复用表面/占据索引及部分代价缓存，但每个目标仍建立 A* 队列、g/came/closed，逐个扩展 XYZ 26 邻域并验证连续边。不能表述为每次完全重建地图；主要缺的是可复用的表面连接图。
- DimOS 还执行 string pulling 和贴合表面的 elastic-band smoothing；灵途当前全局直接输出格路径，局部 SCAN 另生成样条。全局路径外观更平滑不等于速度、加速度和实际机身执行已经验证。
- 当前全局没有独立 yaw/roll/pitch 搜索；支撑、步高、坡度和圆柱净空仍在。局部碰撞、跟踪和明确要求的终点朝向仍考虑 yaw。
