# 机体表示与朝向搜索：2026-10-25 对照结论

本轮只改变一个行为：全局搜索前尝试完整检查过的直接姿态路线。没有替换
RobotConfig 默认模型，没有安装依赖、增加 ESDF/FCL、引入在线 FK 或启动实机。

## 已确认的问题与修改

原固定朝向引导使用覆盖所有 yaw 的外接圆提出 XYZ 路线，再按起始 yaw 验证。
因此“起点转正再直穿门洞”也可能被送入完整姿态搜索。单盒与多部件在同一个
对齐门洞夹具都出现 10 秒截止，不能把这个问题单独归因于多部件几何。

现在先依次尝试起始朝向、起终点连线方向和明确要求的目标朝向，跳过重复方向。
每个候选由起点转向、固定朝向平移、目标转向组成；仅对等高起终点尝试。
沿线保留三维支撑和自由/占据/未知证据检查，全部平移和转动都经过原 BodyQuery
连续扫掠。支持检查按小段执行并观察取消。候选失败继续原有引导和 XYZ+yaw 搜索，
不把直线失败解释成无路，不吸附或挪动真实起点。没有生成耦合平移/旋转边。

这是一项直接连接启发式，不是新的完整搜索算法，也不承诺最优运动时间。
没有实现论文中的 ESDF、Lazy PRM 或 Proxima；不能将本次改动称为那些方法的复现。

## 同条件原生结果

同一 Windows Release 构建设置，同一地图、起终点和搜索参数；每个模型三次，
交替模型顺序。独立 session 先 prepare 后计时，每次 10 秒合作截止。
比较单 OBB（0.96×0.51×0.34 m，中心 Z=0.07 m）与现有 34 部件 BODY2
（加载默认余量 0.02 m）。它们的占据范围、余量和足部支撑语义不同，属于现有
两种配置比较，不能解释为完全相同几何下只比较数据结构。

| 场景 | 单 OBB 修改前→后，中位数 ms | 多部件修改前→后，中位数 ms | 修改后结果 |
|---|---:|---:|---|
| 对齐后穿门 | 10,047 截止 → 67.71 | 10,014 截止 → 45.44 | 两者 3/3 成功 |
| 双门绕行夹具 | 1,921.67 → 43.34 | 747.71 → 40.03 | 两者改为直接通过窄门，3/3 成功 |
| L 形通道 | 137.39 → 116.27 | 779.83 → 799.21 | OBB 0/3；多部件 3/3 |
| 空地 | 45.47 → 22.10 | 66.64 → 28.24 | 两者 3/3 成功 |
| 地面断口 | 10,024 截止 → 10,021 截止 | 10,014 截止 → 10,007 截止 | 均未返回路径，快速无路判断未解决 |
| 0.28 m 过窄 | 1.44 → 0.99 | 4.00 → 2.35 | 均拒绝起点 |
| 上层地面 | 72.49 → 16.35 | 88.03 → 14.98 | 在 Z=0.85 m 的机体位置规划，均 3/3 成功 |

84 次原生运行，所有成功路线均由同一 BodyQuery 实现复查通过。这不是独立
数值算法验证。首次 baseline 测量与编译有部分重叠，机器非隔离；不据此报告
精确提速倍数或目标板实时性。尤其不能将“超时→成功”写成固定倍数加速。

## 模型选择不能只看数量

Go2 固定原始部件的包围范围约为 X=[-0.358,0.340]、Y=[-0.164,0.164]、
Z=[-0.320,0.232] m（尚未叠加查询余量）。当前单盒下沿只有 -0.10 m，
没有覆盖整个腿部。因此它并非完整多部件的保守超集。多部件也只是固定站姿，
不等于行走包络；当前没有理由因本次测试再次切换默认模型或缩小余量。

缓存命中率不能说明 SAT、支撑和缓存访问各自的耗时占比。本轮确认的是减少搜索
候选能解决简单穿门等待；尚未完成函数级成本分解或证明少量部件模型优于两者。

## 物理执行结果

现有 Thunder V4 策略、解析平地、原生单 OBB 全局规划→SCAN→Executor→MuJoCo，
目标前进 6 m 并转向 90°。日志确认使用 `direct_pose_route`。

- 全局规划 176.96 ms；首次非零指令收到时间约 1.295 s，不等于首次实际位移。
- 原生执行 17.92 s 到达；物理记录含到达后保持为 18.74 s。
- 净位移 6.011 m；终点 XY 误差约 11.45 mm，yaw 误差约 0.322°。
- 3,748 个物理子步，非法接触为 0；原生最终几何拦停为 0。
- 本次配置最大线速度范数 1.414 m/s、最大加速度 4 m/s²；实际指令峰值约
  0.75 m/s。它与历史参数不同，不能拿历史时长作配对提速结论。

这是 Thunder 组件物理验证，使用既有静态地图与平面世界的共同范围；不是 Go2、
传感器建图、完整 Product/DDS/driver 或硬件运动验证。
