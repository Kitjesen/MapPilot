# 固定机体查询复用：试验与取舍

## 最终代码

只保留固定 Body 的扫掠半径复用。`collision::sweepRadius(body)` 沿用原来逐部件、
逐角点的算法，包含原 Body margin；`BodyQuery` 构造时准备一次，随后逐边使用
`sweepBound(radius, from, to)`。公式和计算顺序保持为平移长度加半径乘最短转角，
原采样间距、样本余量、中间姿态检查没有改变。BodyQuery 的 Body 在其生命周期内
不改变；新 Body 必须创建新查询。现有 SCAN 调用仍使用原 Body 接口。

曾实现同一姿态先准备部件变换，再复用于体素相交循环。但三组固定查询对照没有
稳定的整体收益：第一次组合版本的七场景查询中位数之和，OBB 637.306→710.702 ms，
多部件 466.426→519.237 ms；另两次有快有慢。不能将源码上减少计算直接当作测速
结论，因此撤回该运行时接口和接线。源码和二进制保留在实验目录的 `updated/`。

## 证据

- baseline、组合版本、radius-only 各 42 次规划：七场景×两模型×三次，共126次。
  两个候选分别与 baseline 比较，返回路径、成功状态、失败原因和扫掠复查结果一致。
- 每组固定查询含64个姿态和64条边，七场景、两模型、五次重复。radius-only 与
  baseline 的8,960个显式查询结果逐项一致；姿态失败原因、命中部件及内部姿态
  查询次数也相同。组合版本同样通过了这项对照。
- 同一个测试程序内交替执行六组、每组20,000次扫掠上界计算。逐次计算半径的中位
  时间102.7305 ms，预先准备半径后0.31035 ms，累计计算结果相同；约每条边节省
  5.12 μs。这是该算子的成本，不是整次规划的提速比例，不含每轮一次准备的成本。
- 整次规划测量仍有明显桌面负载波动，未证实稳定加速。原始较慢结果也保留，
  不能只引用较快的一轮。L形通道仍是OBB拒绝/多部件通过，支撑断口仍10秒截止。
- 几何与全局机体查询回归通过。新增半径回归核对偏置部件、原余量和运动上界。

这轮没有缩小几何、调整余量、减少采样、关闭支撑或未知空间检查，没有部署机器狗。
固定站姿的有效范围没有扩大：它只能表示导出关节角下的几何，不能代替实际摆腿、
机身倾斜和足端承载状态。当前 Go2 配置保持原样，不把该配置当作已通过实机资格。
