# 导航职责收拢：2026-11-08

本轮约束：减少重复决策与中转，不新建总调度框架。另一个会话负责到达／跟踪修改，本轮不覆盖 Executor 或 Follower 的那些修改。

## 先确定谁提供数据，谁做决定

位置、实测速度、地图由定位、驱动和地图模块提供。Executor 接收它们，不能被描述成生产这些数据的模块。局部规划确实需要位置、参考、障碍与速度限制；需要简化的是中途重复组装、转换和管理，而不是删除规划依据。

| 归属 | 应承担的责任 |
| --- | --- |
| 端点的任务／控制管理 | 接受任务、人工接管、取消、最终发布事务。 |
| Executor | 执行已接收路线或辅助运动意图，调用局部规划和跟踪；不是系统总任务管理器。 |
| SCAN FSM | 局部轨迹的状态和切换动作：何时生成／重算、何时接管或丢弃。不是整台机器人的统一状态机。 |
| Manager 与优化器 | 按指定边界计算曲线，检查时间、动态约束和几何。 |
| Backend | 输入适配与结果表示转换；需要逐步移出其额外的轨迹生命周期决策。 |
| Task | 线程、输入快照和结果交接；不再发明一套规划决策。 |
| Follower / FinalControl | 前者拥有实际跟踪进度并计算候选速度；后者检查并反馈实际应用的命令。 |

FSM 可以发起“生成减速轨迹”这个状态动作，但曲线求解仍由 manager 完成；不能把数值算法一并塞进状态机。也不能把局部轨迹状态和任务／驱动状态合成一个全局状态机。

## 本轮先落地的两项

### 删除无效的 `speedReductionPending_`

该标记唯一的置真分支同时清空 `active_`；两个给 `active_` 写入曲线的分支同时将标记置假。因而标记为真时活动曲线必为空，而 `speedReduction` 的必要条件正是活动曲线存在。`speedReduction && !speedReductionPending_` 的第二个条件不改变结果。

删除该成员、全部赋值及该重复条件。保留活动曲线和原有规划状态；连续降速／取消后恢复等既有行为回归验证这个不变量。

### 减速接管由一次 FSM 操作完成

以前 Backend 读取旧曲线导数、调用 manager 的减速求解、单独调用 FSM 的接管／放弃，再手工复制曲线控制点、时间和 ID。一次必须配套执行的操作分散在适配代码中。

现在 `PlannerFsm::startSpeedTransition()` 读取旧参考的垂直速度和加速度，调用已有 `manager.decelerate()`；成功时完成 FSM 接管并导出轨迹，失败时撤回待接收候选并放弃旧曲线。Backend 转换返回的曲线及原有停止原因。没有新增速度阈值、制动算法或另一份持久状态。

此修改收拢的是“求解结果如何改变执行状态”，不是宣称 Backend 已经完全成为无状态转换器。何时触发降速、几何变化后重建 FSM、目标接收标记及停止状态表示，仍需继续收拢。
