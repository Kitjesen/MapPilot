# 现场部署指南

本指南不绑定具体目标，用于在不公开主机名、凭据或留存现场记录的前提下，准备 LingTu 现场目标。请在获授权的建图或导航会话前使用。

> **Status:** 当前、目标无关的部署指南<br>
> **Audience:** 部署工程师、现场集成人员和受监督的操作员<br>
> **Runs on:** 受支持的机器人侧 Linux 目标及已批准的开发主机

> **执行边界：** 部署会改变软件、配置、进程归属，有时也会改变持久化的地图或会话状态。它不是导航命令，但可能为命令接收端做准备。请保持机器人静止，并且只遵循经批准的本地操作规程。

## 部署建立什么

部署使特定目标能够运行选定的 LingTu profile；它并不证明机器人已可移动。现场就绪还取决于正确端点、活动地图、定位、标定、路线预览、命令归属和安全状态。

| 层级 | 部署建立的内容 | 它不证明的内容 |
| --- | --- | --- |
| 源码与依赖 | 选定修订、Python 环境和原生构件已协调安装。 | 现场 profile 能连接硬件。 |
| 运行时服务 | 原生 DDS 服务与 LingTu 进程具有预期的归属边界。 | 传感器已标定、数据新鲜或物理上无阻挡。 |
| 配置 | 目标会解析预期的机器人、设备、DDS 和地图设置。 | 该配置属于当前地图或作业区域。 |
| 无运动检查 | 可获得状态、数据流、就绪度和路线预览证据。 | 已获准发送目标、速度或自主任务。 |

## 1. 选择目标和归属模型

复制文件或启动进程前，请在部署工单或运行手册中记录预期目标：

- 选定的产品 profile 和端点；
- LiDAR、IMU、相机和 SLAM 服务的归属者；
- 地图包和预期的定位来源；
- 已批准的部署修订及回滚修订；
- 首次部署后验证的负责操作员；以及
- 本地紧急、恢复和日志采集流程。

LingTu 的现场外层由不可变 `Product` 定义，`ProductControl`
负责切换及进程监督；`Blueprint` 只装配 Python Host 内的 Gateway、Agent、
MCP 和低频适配器。LiDAR、SLAM、实时地图、导航和驱动通过原生 typed-DDS
边界运行。不要为了让临时工作站命令成功，而把现场 profile 改成依赖 ROS
或 Python 高频处理的运行时。

对于真实导航现场 profile，机器人侧 SLAM 服务拥有传感器生命周期，并通过原生端点适配器发布状态和定位。除非有意改变并重新验证传感器/进程设计，否则不要用本地托管的 localizer 替代这一归属模型。

## 2. 准备可复现构件

使用[构建指南](../01-getting-started/BUILD_GUIDE.md)准备选定的 Python 和原生构建输入。未解决的 lockfile 应视为环境完整性故障：请恢复预期依赖状态，或进行经过审查的依赖更新。不要在现场目标上悄悄运行未锁定的安装程序。

| 配置 | 用途 | 部署前复核 |
| --- | --- | --- |
| config/robot_config.yaml | 几何、标定、坐标系和物理参数。 | 目标身份、标定修订和坐标系假设。 |
| config/devices.yaml | 硬件/设备注册表。 | 选定 profile 使用的设备归属和名称。 |
| config/dufomap.toml | 地图清理/构建行为。 | 地图工作流兼容性与存储影响。 |
| Profile 和端点配置 | 产品图与外部进程边界。 | 命令接收端、SLAM 归属，以及仿真或现场选择。 |

绝不要在公开示例中放入 API key、现场地址、凭据或复制的生产地图。请通过经批准的目标配置或受保护环境提供密钥，而不是放入源代码管理或 shell 历史。

## 3. 保持运行边界

使用目标的常规部署流程安装获批准的构件，并保持以下隔离：

- LingTu Host 与机器人侧原生服务可按各自角色独立观测；重启范围、顺序和就绪检查由当前 RunPlan 与 ProductControl 统一拥有。
- 地图包必须保持完整；不要把单个点云或规划器构件复制到其他目录后称为已恢复地图。
- 活动现场端点必须保持显式。任务 profile 本身并不代表一个安全或获授权的物理连接。
- 使用 ROS 2 时，应将其限制在显式的兼容性/评估工作流中，而不是让它成为隐式产品依赖。

如果部署需要重启服务，请使用已记录的机器人侧运维接口。不要把 Web、REST 或 SDK 教程变成临时的服务管理命令。

## 4. 执行无运动验收检查

请在已部署目标或经批准的远程操作会话中运行以下命令。它们只检查控制/数据流状态，不会提交目标或速度命令。

    bash scripts/lingtu status
    bash scripts/lingtu health
    bash scripts/lingtu doctor --non-motion --json --strict

**预期结果：** 每个命令都会标识选定运行边界，并报告受限的健康状态或具体阻塞项。请将输出随部署记录保存。

**停止条件：** 端点错误、数据流过期或缺失、标定检查失败、定位不健康、地图构件无效、安全停止、控制归属不明确，或缺少原生命令边界。

## 5. 单独证明已保存地图的就绪度

对于基于已保存地图的导航，请在不下发运动命令的情况下检查地图溯源，并评估精确路线：

    bash scripts/lingtu saved-map-artifact-gate <map-directory> --require-occupancy
    bash scripts/lingtu system-acceptance --map <map-name> --goal <x> <y> <yaw>

`system-acceptance` 默认不下发运动命令，并由 ProductControl 管理所需的 Product 切换与清理。其成功仅表明所选地图、位姿、规划器与目标足够兼容；它不授权导航目标。应修复地图、定位或配置边界，而不是用原始速度绕过规划器。

## 6. 交接给受监督操作

只有在部署和无运动证据均正常后，获授权的操作员才能启动受监督的建图或导航工作流。交接必须明确：

1. 活动地图和定位来源；
2. 当前选定的 profile 和端点；
3. 操作员、控制客户端和预期速度来源；
4. 停止/取消/恢复流程；以及
5. 适用于本次会话的现场门槛或验收记录。

在暴露运动能力客户端前，请阅读[安全与控制边界](../10-safety/README.md)；地图或导航流程见[任务指南](../05-guides/README.md)；运行中系统的观测与恢复见[运维](../06-operations/README.md)。

## 部署复核清单

- [ ] 已知构件修订和回滚修订。
- [ ] 设备、SLAM 与命令边界的归属符合 profile。
- [ ] 已针对该目标复核配置和标定。
- [ ] 密钥受到保护，公开材料不含现场凭据或端点细节。
- [ ] status、health、无运动 doctor 和内部计划预览通过，或有明确的阻塞记录。
- [ ] 在进行运动复核前，已保存地图构件和精确路线检查通过。
- [ ] 有人工操作员负责从部署证据切换到受监督的现场操作。
