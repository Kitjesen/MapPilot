## SIM: native Follow

[![MuJoCo 跟随预览，原视频 6–18 秒片段](sim-follow.gif)](sim-follow.mp4)

**输入和过程。** 在 MuJoCo 的受控人物场景中，从衣服颜色像素提取目标，再通过 RGB-D
投影生成目标位置。项目的 VisualServo/PersonTracker 提交目标，原生导航执行规划和
局部碰撞检查，经仿真驱动产生物理运动。结束时检查导航输出、控制权和实际应用的零命令。
这是隔离导航链路的组件测试，使用仿真位姿输入；不包含 Fast-LIO2 验收。

**记录结果。** 12 个 Follow 目标被接受；人物移动 3.0 m，仿真机器人路径长 3.5164 m；
最终导航子目标 XY 误差 0.1656 m。7714 个可见仿真步的碰撞统计为 0，统计不含自身碰撞和
地面支撑。逻辑零输出、控制权清除及仿真步应用停止命令均通过。最终子目标误差不能解释为
机器人到人物的跟随距离；两者是不同指标。

**视频。** 34.75 秒，960×540、4 FPS，139 帧。视频中的全局/局部路径、轨迹和 LiDAR
覆盖来自同一次运行；报告记录 139/139 帧与对应规划调试标识对齐。

**证明范围。** 证明这次受控视觉输入到原生导航、仿真运动和停止的组件链路。它没有使用
学习型人物检测，也没有验证多人重识别、完整 Product/Gateway 启动、Go2 步态或实机运动。
视频不作为 2026-10-14 新观测契约的运行证明。

历史源目录：`build/person-follow-native-20261009-tolerance-fix/`。
本目录 [results.json](results.json) 摘取该运行的 `summary.json` 和
`native/motion/report.json` 关键结果，移除了机器路径和内部进程标识；完整原始包仍留在本地。

## REAL: recording and replay

[![实机录制回放，原视频 22–32 秒的遮挡与重新出现片段](real-replay.gif)](real-replay.mp4)

**采集。** Go2/NX 固定 D435i 在机器狗静止时录制 1341 对同步 RGB-D，覆盖 44.964 秒，
约 29.801 对/秒；记录中的 RGB/深度时间偏差和拒读均为 0，有 8 次源序号增量未采入。
采集过程中没有发送跟随或运动命令。[无跟踪标签的原始 RGB-D 预览](real-rgbd.mp4)
与 [算法回放](real-replay.mp4) 分开保留。

**算法过程。** 在研究服务器 RTX 5090 上，按源顺序处理全部帧，使用 YOLO 检测、
CLIP 文本/外观匹配、DINO 外观参考和 Qwen 身份核验。身份核验保留多视角参考和连续
三帧候选证据；绿色框表示本帧接受的目标，灰色框只是候选，缺失和 UNKNOWN 不做插值。

**观察结果。** 第 58 帧首次选择目标；共有 617 帧被接受。遮挡后原生轨迹 ID 从 1 变为 9，
第 773 帧重新接受目标，距较完整身体重新出现约 0.600 秒。15 次 Qwen 请求得到 8 次 MATCH
和 7 次 UNKNOWN。对这段录制的 617 个接受框做过人工复核，未发现把猫接受为目标；
这只是单段视频的复核，不能当作多人识别准确率。

**仍未证明的部分。** 视频只有一名目标人物，不能证明相似行人干扰下不会跟错。
54 帧位置被拒绝，重新出现时还观察到椅背深度污染。三维位置是相机局部前/左/上坐标，
没有记录地图位姿，相机到机体外参也未验证。它不能证明世界坐标准确、NX 板端实时推理
或机器狗已经完成运动跟随。

历史源目录：`build/dino-camera/field-20261012/`，子记录为
`results/follow-003/field-evidence-summary.json` 和
`follow-003-tracking/render-summary.json`。公开摘要见 [results.json](results.json)。
原始 RGB-D 图片、模型输出和人物裁剪审计包未随这个展示目录整体上传。

## Web interface checks

![导航目标预览界面](navigation-ui.png)

截图使用真实 Topbar/SceneView 组件和模拟 Gateway，日期为 2026-10-09。画面中的地图、
机器人和状态数据来自 fixture；没有连接 DDS、MuJoCo 或实机。它展示的是交互过程：

1. 点击三维目标，自动请求路线预览。
2. 修改高度或导航参数重新预览；这些动作不下发运动。
3. 点击“开始导航”才提交一次目标。
4. 新目标替换旧目标、按 Escape 或取消后，迟到的预览不能恢复旧卡片和路线。
5. 无可行路线时显示原因；重试成功后才恢复开始按钮。

历史浏览器测试的请求统计：

| 操作组 | 预览请求 | 运动目标请求 | 记录结果 |
| --- | ---: | ---: | --- |
| 自动预览、位姿/参数变化、点击开始 | 5 | 1 | 通过 |
| 快速更换目标，只有最后一次生效 | 2 | 0 | 通过 |
| 延迟预览期间 Escape / 取消 | 2 | 0 | 通过 |
| 预览失败后重试 | 2 | 0 | 通过 |

1440×900 和 768×900 的明暗主题均未出现横向溢出。导航截图来自
`build/ui-simple-goal-20261009/` 的浏览器报告；[巡检截图](inspection-ui.png) 来自
`build/ui-typography-inspection-20261009/`，同样使用模拟 Gateway，不是现场巡检通过记录。

## 如何更新这些展示

保留每次验证的输入、运行结果和未通过项，再选取小型展示副本。更新本目录时一并修改
本页和 `results.json`，让媒体日期、验证范围和数值能互相对应。不要用本地绝对路径、
被忽略的 `build/` 链接或文字叠加演示替代可访问的测试证据。

完整流程的验收规则仍以 [Testing and Evidence](../testing.md) 为准。
