## 一、代码实现（数据流路径）

调查范围：`src/runtime/blueprints/stacks/lidar.py`、`src/localization/slam/`、`src/runtime/blueprints/wires/slam.py`、`scripts/deploy/thunder/`、`src/localization/fastlio2/`。

### Canonical 契约

| 项 | 值 |
|---|---|
| 雷达点云 topic | `/lidar/raw_frame`（`TOPICS.raw_lidar_points`） |
| IMU topic | `/imu/raw` |
| 雷达原始 frame_id | `livox_frame`（规范别名 `lidar_link`） |
| SLAM 输出 topic | `/slam/odometry`、`/slam/registered_cloud`、`/slam/map_cloud`、`/slam/localization_health`、`/slam/localization_quality` |
| SLAM 里程计 frame | `odom`（child `body`） |
| SLAM 地图点云 frame | `map`（field 契约强制仅 `map`） |
| frame 链路 | `lidar_link` →(外参 r_il/t_il)→ `body` →(SLAM 状态估计)→ `odom` →(map_odom_tf)→ `map` |

### 三条部署路径

1. **进程内 Native**（dev/map 等 profile）：`LidarModule`（`raw_scan`/`imu` 端口）→ 显式 wire（`src/runtime/blueprints/wires/slam.py::sensor_feed_specs`，`transport=dds`）→ `SlamModule`（`lidar_raw_scan`/`lidar_imu` 端口）→ C++ Fast-LIO2 binding → `odometry`/`registered_cloud`/`map_cloud` 端口。
2. **Thunder field 生产路径（本次机器实际在跑的路径）**：Python 图里**不含** `LidarModule`，雷达→SLAM 完全在两个 C++ systemd 服务间完成：
   - `lingtu-livox-dds.service`（`livox_sdk2_stream --dds`）发布 `rt/lidar/raw_frame` + `rt/imu/raw`
   - `lingtu-slam-dds.service`（Fast-LIO2 native cyclone runtime）订阅上述 topic，发布 `rt/slam/odometry`、`rt/slam/map_cloud` 等，并写快照到 `/tmp/lingtu_slam_status.json` + `/dev/shm/lingtu_slam/`
   - `CppSlamStatusAdapterModule` 把快照桥接回 Python Module 图（Navigation/Gateway 等消费方）
3. **MuJoCo 仿真**：`sim_lidar()` 生成的点云走外部 Fast-LIO 或 native DDS，路径与生产链一致，仅数据源不同。
