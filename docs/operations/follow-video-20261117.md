# 人员跟随真实视频验证 — 2026-11-17

结论：**本轮未达到持续稳定跟随的验收要求。** 检测召回、身份保持、重获等待和实时吞吐是不同问题，不能以“没有误跟”代替连续性。

## 本轮实际运行

- 当前工作区代码：`YOLOWorldDetector → NativeByteTracker → PersonTracker`；重获核验调用真实 `MoonshotClient / kimi-k3`。
- 公共视频：MOT17-09-FRCNN 全部 525 帧，30 Hz，17.47 秒。从官方 ZIP 提取 JPEG 后编码为回放视频。GT 只在跟踪结束后用于归属评分，不参与检测、选人或身份核验。
- 现场录像：`build/dino-camera/field-20261012/follow-003` 原始 RGB-D PNG，1341 对，44.96 秒。第 58 帧选择黑色上衣、蓝色裤子的人员。
- 每帧重新进行 YOLO-World 推理；DINO 特征重新计算。没有用旧检测结果替代这两次主试验。
- 相同检测结果分别送入默认无外观编码器的 PersonTracker，以及 DINO + 原始目标记忆 + Kimi 的对照组。
- 当前回放工具原来的 baseline 带有 CLIP，本轮实验适配器明确替换为无编码器的 PersonTracker，以匹配本地默认配置。只改实验适配器，未改生产算法。
- 硬件：本机 RTX 5060 Laptop 8 GB；PyTorch 2.10.0+cu128、Transformers 5.1.0、Ultralytics 8.4.21。不是 NX 实测。
- 权重：既有 YOLOv8s-Worldv2、CLIP ViT-B/32、DINOv3 ViT-S/16。CLIP TorchScript 转为 state_dict，并移除三个标量元数据键；训练权重未替换。
- 没有连接机器狗驱动、没有执行运动、没有变更 NX 服务。

实验文件和重放脚本位于 `build/person-follow/video-20261117/`：
`run.py`、`render.py`、`diagnose-mot.py`、`compare-bytetrack.py`、`host-diagnostic.py`。
`run.py` 复用 `tools/datasets/dino_follow.py`，只替换 baseline 配置、身份核验后端和进度日志；没有伪造模型输出。

## 多人视频：误跟没有出现，连续性严重不足

按目标框与 MOT 标注 IoU ≥0.5 归属，初选人物为 GT 22：

| 路径 | 正确归属原目标 | 归属其他人 | 输出但无法归属 | 无目标输出 |
|---|---:|---:|---:|---:|
| 默认无外观的跟踪组件 | 13 | 0 | 2 | 510 |
| DINO + Kimi 组件对照 | 24 | 0 | 0 | 501 |

这是本次选定目标的归属统计，不是标准全场景 MOT 分数。目标有 392 帧标注；其中可见度至少一半的 296 帧里，默认组正确输出 13 帧，对照组 16 帧。不能把全部“无输出帧”都解释成故障，因为后段目标已离开标注。

本片只有 RGB，没有度量深度；默认组的距离重获条件缺乏三维位置，因此主要依赖原始 ID。结果不能直接等同于 RGB-D 实机的整体表现。

对本轮新计算的检测框作独立诊断：

- 可见度至少一半的 296 帧中，292 帧有匹配目标的检测框。
- 当前原生关联输出在其中 291 帧有匹配框，但同一标注人物对应 8 个 ID，相邻可归属观测之间发生 13 次 ID 变化。
- 对照组有 455 帧处于身份请求进行中，说明低频云端核验被频繁触发，无法承担连续跟踪。
- Kimi 返回 3 次 MATCH、6 次 OTHER；部分回执因候选已变化被丢弃。MATCH 不是自动恢复运动的证明。

在同一批**本轮新推理得到的检测框**上，使用已安装 Ultralytics 的参考 ByteTrack 进行关联诊断：初选 ID 的正确归属输出为 102 帧、误归属 0 帧；同一标注人物的 ID 变化为 9 次。它优于当前原生关联，但仍不够稳定，且没有接入生产。此项是缓存检测框的诊断对照，不是第三次完整图像推理。

## 现场 RGB-D：必须区分组件与 Host 门禁

| 路径 | 接纳目标帧数 | 最后接纳帧 |
|---|---:|---:|
| 无外观 PersonTracker 单独回放 | 799 | 1114 |
| DINO + Kimi 组件对照 | 329 | 621 |
| 默认 VisualServo 主链路追加诊断 | 780 | 939 |

现场录像没有逐帧人物身份 GT，不把“接纳帧数”当成“正确率”。抽查图和完整视频用于人工核对。

无外观组件在 1094–1114 帧间接纳了 19 个猫的观测；截图可见其不是初选人员。**这不能直接证明 App 会让机器狗跟猫走。** 随后将本轮检测结果和原始 RGB-D 喂给实际 VisualServo，确认选人后运行其超时逻辑，1000 帧后接纳数为 0，上层挡住了这个具体迟到候选。

追加 Host 诊断复用的是本轮检测缓存，按录像的相对时间加速推进；初选人物的 person verdict 为测试输入。固定相机坐标只用于身份距离判断，没有核验相机到机器狗地图的外参，也没有模拟 native 导航取消回执。不得据此声称物理跟随和停车已验证。

DINO 对照避免了晚段猫候选，但人员在后半段仍出现时未能恢复连续输出；不能把它描述为已完成的改进。

## 延迟与吞吐

两次主回放合计 17 次真实 Kimi 请求，16 次得到响应，1 次约 30.3 秒超时。成功响应约 2.3–12.4 秒。现场还返回了一次 UNKNOWN，不能为了保持连续性将其按 MATCH 处理。

| 数据 | 录像时长 | 热身后处理到末帧的墙钟时间 | 约处理帧率 |
|---|---:|---:|---:|
| MOT17 | 17.47 秒 | 82.25 秒 | 6.4 FPS |
| 现场 RGB-D | 44.96 秒 | 180.26 秒 | 7.4 FPS |

当前完整逐帧回放落后于输入节奏，不能通过实时验收。这里没有跳过积压帧；真实机器人还应测试最新帧策略与新鲜度门禁。以上是本机实验吞吐，不是 NX 或相机采集帧率。

## 下一步顺序

1. 优先改善原生轨迹关联，利用同一检测输入对比 Kalman 预测、丢失轨迹关联和遮挡处理；不能只提高检测阈值。
2. 让可靠的本地外观与运动连续性承担正常重获，Kimi 留给真正的歧义；同时保留无证据不换人的边界。
3. 用本轮困难帧对比 DINO 与有专用人物 Re-ID 权重的小模型，检查转身、蹲下、局部可见时的误拒绝和误接纳，不堆叠所有模型。
4. 再验证完整 Host 的真实编码器、最新帧处理、native 回执和现场运动。当前受控测试中已复现的短间隔换人路径仍需修复，不能被本段录像的超时保护掩盖。
