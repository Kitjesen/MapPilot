## 本地已修复的软件缺口

### P1：手动重定位阻塞两个主循环

触发：在已运行的定位 Product 中点击网页“自动匹配”或提交手动初值。

- Gateway 原来在 async HTTP handler 中同步等待地图查询和 slamctl，现在这些等待
  都通过 `asyncio.to_thread` 执行，包含全局定位、手动初值和启动地图跟踪三个入口。
- 原生手动请求改用既有 `startRelocalizeAsync / pollRelocalizeAsync`。独立保存请求
  字符串，避免 DDS 回收请求后丢失编号；计算完成并通过原有提交判断后才回复最终结果。
- 手动请求和周期跟踪互不消费对方的结果。正在计算时，新的修改请求明确返回 busy；
  状态查询继续工作，没有无界队列、强制取消或自动重放请求。
- 全局等待由 10 秒改为 45 秒，为 30 秒 BBS 搜索和后续精配准留出时间；slamctl
  的 DDS 等待超时（退出码 4）及进程超时均标记“结果尚未确认”。超时不取消原生计算，
  不等于算法拒绝，也不自动重复提交。

Gateway 回归模拟服务阻塞，检查同一事件循环能执行心跳工作。C++ 请求路由测试使用
可控的未完成注册计算，期间执行 50 次 feed/tick，再检查原请求的最终成功或拒绝回复。
这证明本地调度契约，尚不能替代 NX 慢定位期间的真实 HTTP/SSE、点云和遥控响应验证。
350 ms 运动输入有效期和原生仲裁保持原样。

### P2：网页导航冷启动缺少初始位姿

触发：新地图无可用 seed，或机器狗被移到旧 seed 无法匹配的位置，自动全局定位未通过。

- “使用此地图导航”弹窗新增可选“指定初始位姿”，填写 X/Y/Z（米）与 yaw（弧度）。
  未勾选时继续走原有的同地图历史 seed / 自动全局搜索路径。
- `MapView → App → useProductControl → control_server → ProductControl.switch`
  传递 `initial_pose={x,y,z,yaw}`，控制服务转为 `(x,y,z,yaw)` 并明确启用 relocalize。
- 初值只允许用于 nav，要求四个有限数值。请求回执保留初值；同一 request_id 改初值
  会拒绝，失败后可以用新请求携带初值重试。旧的不含初值的回执保持原有结构。

仍由 ProductControl 完成全部启动事务，SLAM 未对齐时不越过下游就绪判断。
回归覆盖首次定位失败、带初值重试、Gateway 重启查询原回执，以及到 native CLI 的 Z 参数。

### P2：网页初值遗漏地图高度 Z

触发：机器人位于台阶、坡面或地图原点之外的高度，用户通过网页设置初始位姿。

- 手工表单和 HTTP 请求贯通 Z，并说明它是地图坐标中的机身高度。
- Shift+点击重定位同样保留当前已投影到地图坐标中的高度和航向；缺少地图高度时拒绝
  构造点击初值，不用 odom 高度或零值替代。
- 空白、非数值、非有限输入不会再被 `parseFloat(...) || 0` 悄悄替换为零。
  真正填写的零值仍有效；API 保留已有四参数调用的 Z=0 兼容行为。

原生高度修正范围仍为 0.15 m，倾斜仍使用已有测量/完整姿态机制，未放宽配准门槛。

### 联调发现并修复：本地控制连接误用 HTTP 代理

Gateway 到 `127.0.0.1` ProductControl 的连接原来继承系统 HTTP 代理。本机回归出现
代理返回空错误响应；现在该固定回环连接明确直连。测试在配置不可用代理时仍能提交
切换和跨 Gateway 重启读取原回执。
