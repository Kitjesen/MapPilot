## Findings and bounded changes

1. **Device identity corrected.** The preceding deployment work incorrectly
   replaced SDK serial `419522073370` with USB/V4L identifier `253843060949`.
   The original successful capture command and streaming evidence in
   `build/go2-camera-20261010/runtime92.json`, plus the SDK enumeration recorded
   in [the October 10 field record](go2-camera-20261010.md), distinguish them.
   RobotConfig again uses the SDK serial, and the correction is installed in
   `.94`. A fresh October 25 NX SDK enumeration independently confirmed the
   same serial. This establishes device selection, not stream quality or
   camera-to-body extrinsics.
2. **Repeated slow-stream exposures.** The official SDK permits a slow frame
   to appear in more than one frameset when stream rates differ. Capture now
   tracks the SDK frame number independently for color and depth and emits only
   new exposures. Unequal FPS remains supported; the faster stream is not
   throttled to the slower rate. This preserves the existing record/SHM format.
3. **Frame age after clock correction.** Native WHEP expiry must preserve the
   accepted frame's initial age and accumulate subsequent elapsed time with
   `steady_clock`. New sequence numbers with regressed host timestamps must
   rebind the existing WHEP session rather than wait for wall time to catch up.
   The default 250 ms source-age budget is retained.
4. **Real process initialization.** The GLib portability change uses `GstUri`,
   which requires GStreamer initialization. URI validation must run after
   `gst_init_check()`. A library test that already called `gst_init()` cannot
   establish correct process startup.
5. **Metric meaning.** Camera HUD's former "latency" was calculated from the
   arrival of an SSE heartbeat. It is now labelled heartbeat age. Actual video
   latency remains unmeasured on this candidate.
