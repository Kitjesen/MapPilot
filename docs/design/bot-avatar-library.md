# LingTu Bot 形象库（2026-11-13）

本轮按用户要求接入完整外形库和参考动效，替代“只为原有八个外形补眨眼”的方案。原有配置兼容，形象和预览不改变模型、权限或机器人任务状态。

## 内容与入口

- 会话右上角 Bot → 我的 Bot → 形象库。
- 立体形象 26 个：25 个常规选择器形状和 pumpkin，使用完整网格、眼睛和动作渲染。
- LingTu 重绘 18 个：按用户给出的截图绘制，包含石、听、加、携、点、暖、芽、向、门、流、聚、纳、望、循、息、衡、问、叠。它们不是所提供两个仓库当前版本中的官方 ID。
- 经典外形 8 个：保留 ID、路径与标签，已有名字、颜色、角色设置和 `lingtu.bot-profile.v1` 不变。
- 九种表情、十二种活动和八种业务状态可预览。表情与活动仅用于本地预览，不提交模型或工具请求。
- 大小设置实际用于会话入口；面板明确显示 2× 预览，48 / 64 的预览分别为 96 / 128 CSS 像素。

形状数据源为 `web/src/services/botShapes.ts`。`Bot.tsx` 保留统一入口：立体形象交给 `GrokAvatar.tsx`，重绘与经典外形使用独立头部、目光和眼睑层。所有选择器缩略图静态，不创建持续动画循环。

- [grok-bot-avatar-engine](https://github.com/RongleCat/grok-bot-avatar-engine/tree/a995c0675e36ba113de41ead3a5d9be3fcd567e3)：沿用其引擎绑定、静态渲染和挂载接口。

用户本轮指定本机 `D:\Program Files\Grok Bot\resources\app.asar`。包内 `package.json` 记录版本 **1.0.1**；实际头像声明位于 `dist/renderer/assets/index.eager-common-1bSx8o0X.js`。25 个常规形状、南瓜及九个表情名称与参考目录一致。

参考仓库 0.78.1 的闭包在实际动态渲染中存在缺失自由符号。本轮没有猜测这些参数，而是使用 TypeScript AST 和绑定符号关系，从用户本机 1.0.1 的脚本中抽取完整头像声明闭包：**777 个声明，原始导出前约 216 KB，无外部模块导入，no-undef 零诊断**。逐条声明保留 source character offset；仅在导出处增加可读接口所需的旧名别名。应用启动、账号、通信和原生模块不在该闭包中。

REA 先检查包入口，再限定分析上述 renderer 文件。父证据分别为 `ev_9079c3cdb56af0084aee20fbccbd912a1b31cb6dae53b5f712cdf943216507c8` 和 `ev_62c093e0f4501f0fd3a9e3b7f0084ba76dd0bcb3cc9c1f7ac481249b3916df3b`。分析为静态、范围覆盖 partial，不能当作官方客户端逐帧运行对比。ASAR 的若干 unpacked 原生组件存在声明校验差异，工具按 record-and-continue 记录；本轮没有执行或接入这些组件。

核心及接口在 `web/src/vendor/grok-avatar/`，具体本地补丁、原作者 MIT 许可与上游权利说明在该目录 NOTICE.md / LICENSE。不把本机渲染代码称为作者原创或自动归入其 MIT 许可。

## 状态与生命周期

业务状态仍由当前会话事件推导。待审批优先；处理、真实工具运行、正文输出、完成、失败与未连接各自映射到对应表现。完成不因打开历史而重复庆祝。活动预览退出后回到所选身体，不重置为默认圆形。

立体形象每个实例只有一个原生动画循环；页面隐藏和减少动态效果时销毁动态实例并显示静态帧，恢复时重新建立时钟，不补播隐藏期间的动作。卸载清理帧回调、指针监听与观察器。平面形象继续使用独立眨眼调度，并遵守相同暂停与清理规则。

## 本地验证

目录、旧配置、各尺寸 SVG、眨眼、会话状态及原生适配的定向测试覆盖本轮边界。浏览器逐个选择 52 个形状，检查常态眼睛位于实体、参考检索动效、减少动态效果、尺寸保存与刷新恢复、手机宽度和会话入口。演示页为 `/tests/bot-motion-preview.html`，状态与活动由控件模拟，不连接真实模型或机器人。

本轮 70 项相关检查通过（目录 2、资料 4、眨眼 5、会话 UI 49、真实原生适配 10）；尺寸修改后旧测试中的固定 32px 定位已调整，相关回归再次通过。适用 TS / TSX 的 ESLint 与全站生产构建通过，声明文件由 TypeScript 检查。构建保留共享工程已有的大 chunk / 重复静动态导入提示，未为此扩展改动。

动态显式表情通过唯一的本地 `holdExpression` 控制器方法保持；传入 null 时恢复当前原生状态的默认表情轨道。普通待机、工作和流式回复不固定为 neutral，保留片段自带的表情与眨眼。

实现验证结果与录屏位于工作区 `outputs/lingtu-bot-library/`。没有修改本机 Grok 安装包，也没有重启共享 Host 或执行机器人任务。
