## 对标结论

### 1. 主菜单和暂停菜单不是同一屏

主菜单回答“我现在要开始什么”；暂停菜单回答“我当前正在做什么”。两者都保留稳定的返回和焦点行为，但暂停菜单必须保留游戏上下文。

LingTu 当前规则：

```text
欢迎页
  ├── 开始
  ├── 设置
  └── 退出

开始
  ├── 选择机器人
  ├── 选择地图
  └── 进入场景

驾驶暂停
  ├── 当前任务 / 当前会话摘要
  ├── 继续游戏
  ├── 任务日志
  ├── 机器人与地图
  ├── 重新开始
  ├── 设置
  ├── 返回主菜单
  └── 退出游戏
```

暂停菜单不加入“切换视角”“运行信息”这类技术动作；它们属于驾驶输入或辅助面板，不应变成主菜单条目。现有自动化测试已经固定了这一边界。

### 2. HUD 只显示玩家此刻需要的内容

现代游戏通常把 HUD 分成三层：

| 层级 | LingTu 内容 | 显示策略 |
| --- | --- | --- |
| 持续层 | 当前任务、危险/连接状态、速度 | 常驻但低密度 |
| 情境层 | 路线、目标、停稳/采集/验收阶段 | 有任务才显示 |
| 辅助层 | 详细状态、传感器、帧率、记录状态 | F1/TAB 或设置中打开 |

因此默认驾驶画面不应持续显示会话摘要、传感器细节或完整快捷键表。F1 打开操作帮助，Tab 打开只读状态面板，Esc 打开暂停菜单。

### 3. 游戏世界保持可见

暂停菜单采用左侧信息列＋半透明渐变遮罩，右侧保留场景和机器狗，不使用全屏不透明设置面板覆盖整个画面。设置页可以使用更高对比的内容面板，但返回后必须恢复驾驶输入和焦点。

### 4. 选择页是内容浏览器，不是配置表

机器人和地图选择页保留两个独立步骤：

```text
Step 01  机器人
  分类、搜索、列表、3D预览、能力状态

Step 02  地图
  场景缩略图、环境信息、可运行/仅预览状态、预览

Step 03  出发
  机器人 + 地图 + 任务摘要 + 运行条件确认
```

`Step 03` 不是第三个重复选择页面，而是开始前的最终确认页。若当前流程不需要确认页，按钮可以直接显示“开始”，但内部仍要经过同一份 SessionSpec 校验。

### 5. 操作焦点优先于鼠标装饰

所有菜单必须同时支持：

- 鼠标悬停和点击；
- 键盘上下左右、Enter、Esc；
- 手柄方向键、确认、返回；
- 打开页面时拥有确定的初始焦点；
- 返回上一页时恢复上一个合理焦点。

当前 `LingTuSimUI` 已经使用 Slate focus marker、设置页 Tab 切换和选择页初始焦点；后续改版不得用绝对像素位置破坏这些行为。

## 本轮代码调整

暂停菜单现在显示：

```text
当前任务
机器狗巡检 · route_id
会话已绑定 / 控制已绑定
```

这让玩家不用打开“运行信息”页面就能理解当前上下文，同时保留真实会话状态来源。没有绑定任务时，显示自由驾驶/模型预览等真实状态，不伪造任务。

实现位置：

- `sim/runtime/visual/RobotSimUE/Plugins/LingTuSim/Source/LingTuSimUI/Private/SLingTuSimFieldInterface.cpp`
- 任务文本由 `GetDriveMissionText()` 提供；会话文本由 `GetDriveSessionText()` 提供。

## 下一批 UI 实现

1. 选择页改成统一的 `ContentBrowser` 视觉语言：左侧筛选/列表，右侧 3D 预览和能力信息。
2. 地图选择页加入环境缩略图、可运行条件和预览状态，但不把未绑定的预览标成可驾驶。
3. 增加最终“出发确认”状态，不重复显示一整套配置。
4. 将场景内底部键位提示默认收敛为 `F1 操作 / Esc 菜单`；详细操作只在 F1 面板出现。
5. 在 16:9、21:9 和窗口模式下验证锚点、字体、焦点和安全边距。
6. 为暂停、设置、机器人选择、地图选择和最终确认补充统一的屏幕栈行为和回退测试。

## 不做的事情

- 不直接复制 Hogwarts、Breakpoint 或其他商业游戏的 UI 图片和资源。
- 不把技术诊断页面伪装成玩家菜单。
- 不用 UI 显示“已完成”来替代真实任务、传感器或物理状态。
- 不因为对标 3A 就增加不必要的动画、发光、复杂角标或持续滚动文字。
