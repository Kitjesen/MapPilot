日期：2026-10-18

## 结论

LingTu 不需要同时堆出许多大地图。优先完成一段**山地林道视觉/可驾驶纵向切片**：地形、道路、材质和机器人必须真正接地，再用同一套任务、接管、证据与回放机制扩展到工厂、仓库、地下管廊等环境。FactoryPark 保持为现有运动和巡检接线的参考场景，不为“数量”导入新机器人。

## 当前基线与目标边界

### 已有基础

- 产品链已有两步选择：欢迎页 → `01 机器人` → `02 地图/任务`，地图页直接进入，不增加第三个确认页；最终能否启动仍由已编译选项和 ProductControl 决定。
- inspection Product 支持地图绑定路线、原生点位推进、暂停/继续/取消、有限循环和失败策略。当前地图身份是 `map_id + content_epoch`，路线内容另由 `route_revision` 固定；不再使用旧的 `map_version` 表述。
- 原生导航和安全链拥有自主运动与人工接管仲裁。人工释放控制后必须显式继续任务，松开按键不等于自主巡检已经恢复。
- UE 已有 Slate 选择界面、只读运行状态投影、目标方位/离屏提示和巡检阶段显示；这些组件和自动化结果不等于完成过一场同会话自主巡检。
- Recorder/replay 已有真值/命令记录、UE-only 视觉回放、RGB/depth 与 typed-DDS 载荷记录代码；这些组件能力不代表 Studio 触发的完整回放和正式同会话资格结论已完成。
- 当前配置根是 `config/system/`；Python 仿真测试位于 `tests/sim/`。新设计不得复活 `config/runtime_graph/` 或 `sim/tests/`。
- 工作区中的山地离线工具正在收口米制地形、三角面一致的高度查询、林道材质掩码与接地；这不是 WorldPackage、UE 场景或机器人已跑通的证明。

### 产品目标

操作员在每个场景里都应能立刻回答四个问题：机器人正在做什么、当前是否安全、谁拥有控制权、下一步需要我做什么。场景只是任务发生的空间；真正可复用的产品能力是：选择、预检、自主执行、人工接管与显式恢复、证据复核、回放和受控制作。

## 场景组合：任务驱动而非资产陈列

| 环境 | 有目的的首个任务 | 可复用机制 | 首个可验收切片与边界 |
| --- | --- | --- | --- |
| 机器人基地 / 出发庭院 | 选择现有机器人与地图，检查会话、地图、传感器和控制就绪后出发 | 两步选择、可用性状态、预检、出生/复位、基地与任务会话分离 | 首页可独立展示，但不能因为机器人可见就启动物理或宣称 ready；不加入账号系统 |
| 山地林道 / 观测站 | 从安全起点沿连续林道到转弯、涵洞边和观测站，完成三个定点 RGB 概览 | 同源高度场、林道掩码、坡面/横坡、边界与接地、远近景分层 | **第一优先级**。先完成离线地形/道路/材质/接地，再接 WorldPackage、MuJoCo 和 UE；坡度与转弯限值以已测控制能力确定，不从概念图猜测 |
| FactoryPark 工业园区 | 南门/装卸区/设备区三点巡检，经历到达、停稳、采集、复核 | 现有运动参考、设备语义点、任务阶段、人工接管、证据分离 | 保持为回归基准；必须在同一 Product/MuJoCo/UE 会话中证明，不把 HUD 打勾或命令 ACK 当完成 |
| 仓储与物流通道 | 沿窄巷道巡查通路与货位端面，在盲角暂停并采集概览 | 窄通道、遮挡、转弯包络、静态障碍代理、路线重规划/受阻解释 | 首版货架和托盘保持静态；只做 RGB 概览与人工复核，不做自主取放、叉车协作或库存识别承诺 |
| 地下管廊 / 电缆隧道 | 在低照明、无 GNSS、可能间歇连接的走廊中完成重复点位巡查 | 低照明、重复纹理、限高/限宽、状态新鲜度、失联保持与恢复 | 先验证定位健康、灯光和 RGB 可用性；不宣称气体、热成像、局放或声学检测 |
| 雨后城市 / 园区道路 | 从路口经路沿坡道到有遮蔽的设施点，检查湿/干路面与无障碍通路 | 路沿与坡道、排水语义、湿材质、可达边界、地图预览 | 湿路面首先只是视觉材质；摩擦、雨雾传感器和行人/车辆必须分别配置并验证，不由画面推断 |
| 室内配电房 / 设备间 | 以可重复观察位姿巡查三面设备柜，采集全景供人工复核 | 门槛、狭窄转身、重复设备编号、观察位姿、证据缺失/重检 | 首版不自动读表、不操作开关、不自动诊断；柜体视觉和碰撞代理必须共享稳定实体身份 |
| 河道堤坝 / 桥下涵洞 | 沿堤顶到桥下净空点和排水设施，遇不可达边缘时停下并解释 | 高差边界、低净空、碎石/混凝土过渡、危险区标记、替代观察点 | 不模拟洪水或水动力；水面和湿痕不自动改变物理，边缘安全仍由原生三维导航与安全链决定 |

这些环境不应各自发明任务系统。优先复用五种机制：同源地形/碰撞、稳定语义实体、地图绑定路线、原生控制权转换、证据与回放引用。只有当机制在较小切片中通过，才扩大场景尺寸与资产密度。

## 不止地图：值得拓展的六个方向

1. **同一场景的不同运营条件**：白天/夜间、干燥/雨后、有无临时障碍。同一资产库产生不同任务约束，但物理摩擦、视觉天气和传感器扰动必须分别配置，不用滤镜冒充真实影响。
2. **任务简报与场景记忆**：进入前看到本次路线目的、设备观察需求和已知阻塞；返回后从同一路线对比两次证据。不增设冗余的第三个进入步骤，简报附在地图/任务选择内。
3. **交互资产的能力说明**：门能转多少、阀门能否旋转、货物是否可推动，应来自实际关节、碰撞和控制合同。已有机械测试不等于机器人会自主操作；首版优先人工触发/受控实验，观测反馈单独记录。
4. **遇阻后的可解释恢复**：显示阻塞原因、定位/传感器状态、人工接管和显式继续入口，而非让机器人一直转圈或静止。不得自动瞬移、跳过安全链或把重置伪装为成功到达。
5. **训练与评估共用一套事实**：自由驾驶用于熟悉相机与路面，正式任务记录到达/停稳/证据。回放对比接管次数、阻塞时段和证据缺失，不凭观感发明评分或宣称算法性能提升。
6. **作者视角与操作员视角分离**：操作员只见开始、任务与必要状态；作者才进入资产检视、碰撞代理、传感器观察位和场景制作。后续编辑器扩展应复用已有导入/编译入口，不把每个运行界面都变成控制台。

这些是产品拓展方向，不是本轮全部实现或默认开启的功能。近期仍围绕单个可验收切片推进。

## 操作者体验闭环

1. **两步选择**：在 `01 机器人` 选择已有受支持机器人，在 `02 地图/任务` 查看兼容、可运行、仅预览、隔离或不可用状态并直接进入。浏览某地图不代表内容已安装、物理已编译或运行已就绪。
2. **加载与预检**：ProductControl 解析并启动固定 `env` 中的唯一 RunPlan，界面只显示实际 `product_session_id`、地图身份、模块和传感器就绪状态，不创建第二套生命周期。
3. **任务受理**：路线冻结 `map_id + content_epoch`、`route_revision`、点顺序、坐标与 Product 会话。请求已受理不等于机器人已运动。
4. **自主巡检**：原生 inspection executor 依次交给现有三维导航链；UE 展示当前点、阶段、控制来源、阻塞原因和下一项操作，不自行判断到达或推进。
5. **人工接管**：操作者发出接管意图，等待原生控制权状态确认后驾驶；任务保持、暂停或取消由原生事件说明。释放人工控制后，操作者显式选择继续或取消，系统不自动恢复旧运动。
6. **证据与验收**：每个动作显示已采集、缺失、过期、无效或不支持。原生任务成功、证据齐全和人工接受是三个不同结果；缺失必要证据进入待复核/重检，而不是伪装为任务失败或完全成功。
7. **复核与回放**：从任务报告进入按时间对齐的事件、位姿、命令、图像和失败原因视图。Recorder 提供证据材料但不重写任务事实；回放也不获得运动或完成权威。
8. **再次巡检**：复核者可基于原路线创建明确的新任务或选择失败点重检；不得修改已经结束的历史任务来伪造一次连续成功。

## 轻量制作流程

避免建设新的“大一统场景编辑框架”。首版制作只需要一条清晰路径：

```text
SceneDraft / 已授权源资产
  → 稳定 entity_id、米制 transform、visual、physics、sensor_surface、semantic
  → WorldPackage（同源 UE 视觉面与 MuJoCo 物理面）
  → 编译 SessionBundle
  → 绑定真实 map_id + content_epoch 的路线
  → ProductControl 运行
  → Recorder 记录与复核
```

- 当前 UE Build/Tactical 面板仍是只读投影，不把它描述成已实现的关卡编辑器。
- 路线制作先复用现有 API/离线工具；只有地图身份、点位和动作通过校验后才保存。
- 视觉资产不能凭外观自动成为碰撞、导航或传感器表面。地形使用同源高程；大石、护栏、设备和建筑使用合格的解析/凸碰撞代理。
- 先复用已验证的 Thunder/现有机器人包。除非新平台本身是交付目标，不为增加选择数量导入新机器人。

## 权威与数据流

| 领域 | 唯一权威 | 本设计中的呈现/消费边界 |
| --- | --- | --- |
| Product、环境、进程生命周期与当前运行 | ProductControl + immutable RunPlan | 选择页发出意图；界面只读当前计划、`product_session_id`、readiness 和失败原因 |
| 巡检路线校验、点推进、重试/循环、任务终态 | 原生 inspection executor / 原生任务事件 | Gateway/UE 投影有序事实；不得从 ACK、Overlap、动画或 HUD 状态推断完成 |
| 自主导航、命令准入、安全、人工接管与释放 | 原生 navigation + safety/control authority | UE/Web 只发送操作者意图并显示 requested / admitted / observed 的差异 |
| 仿真时钟、机器人位姿、动力学、接触、碰撞与射线 | MuJoCo / compiled real-sim world | UE Actor 跟随同代 truth snapshot；UE-only collision 不改变任务或路线结果 |

## 里程碑与量化验收

### 近期：山地第一切片

**N0 — 离线接地样板（本轮主线，不宣称 UE）**

- 默认样板维持米制 `84 m × 84 m`、`129 × 129` 高程采样，林道使用地表材质掩码而非独立悬空带状网格；尺寸可在后续能力实测后调整。
- `tests/sim/` 定向测试应证明：高度查询与生成三角面一致、四条边界可查询、林道掩码不移动地形几何、弯道不越过端点、相同输入可重复生成。
- 输出离线预览、地形/道路参数和测试结果；没有同会话证据时明确写“未启动 UE、未完成 MuJoCo 行驶”。

**N1 — 最小视觉/可驾驶切片**

- 将一段连续林道、一个安全起点、一个弯道/坡面、一个涵洞边和一个观测站编译为同一 WorldPackage；UE 视觉与 MuJoCo 高度场/代理共享坐标、稳定实体 ID 和内容身份。
- 只使用现有机器人包。完成出生接地、前进、转向、坡面、受阻、停止与 Reset；记录机器人 truth，而不是只看 UE 动画。
- 一条三点路线绑定真实 `map_id + content_epoch` 和 `route_revision`。连续 3 次干净运行均无悬空/穿地、陈旧代次或重复事件；其中一次包含自主 → 人工接管 → 释放 → 显式继续。
- 若执行路径仍未绑定，HUD 只显示目标方位和直线估计，不显示地面路线。性能以新鲜同会话证据记录帧时间、实时率、12 秒性能门和 60 秒稳定性，不从设计图预设通过。

### 下一阶段：把机制证明为可复用

- 在 FactoryPark 完成同一 Product/MuJoCo/UE 会话的三点任务，作为运动参考：到达、停稳、RGB 概览、人工接管、显式恢复、任务终态、证据复核全部来自各自权威。
- 选择仓储或地下管廊之一，复用窄通道、低照明/遮挡、状态新鲜度和受阻恢复，不新建第二套任务状态机。
- 将任务事件、控制权变化、位姿/命令和 RGB/depth 载荷在回放中按同一 session/generation 对齐；缺失流明确显示缺失，不补造数据。
- 验收：每个切片至少一条正常流程、一条缺证据流程、一条接管/恢复流程；3 次重跑无旧状态、重复处理器或历史任务被改写。

### 探索阶段：扩大覆盖而不扩大权威

- 雨后城市用于验证湿材质、路沿坡道和可达边界；配电房用于重复观察位姿和人工复核；堤坝涵洞用于高差边界与低净空。
- 基地可发展为内容入口和会话前预检空间，仓库/管廊可共享模块化结构件；它们仍通过同一 Catalog、SessionBundle、ProductControl 和巡检合同运行。
- 只有前一切片留下可重复的运行、证据和性能记录后，才增加天气、动态角色或大场景流式加载。探索项默认不进入交付承诺。

## 明确不做

- 不做战斗、武器、敌人、生命值或战斗化任务表达。
- 不购买 Marketplace/Fab 资产，不把购买或授权流程设为本轮依赖；未经授权的外部内容不进入生产库。
- 不做账号、登录、云存档或多租户系统。
- 不为增加数量导入新机器人，也不把隔离/预览资产包装成可运行平台。
- 不做自主抓取、开门、按开关、搬运或其他操作能力声明。
- 不宣称热成像、声学、气体、局放、自动诊断、趋势分析或工单闭环；除非以后有对应运行合同和验证证据。
- 不让 UE 成为物理、导航、控制、任务完成或证据接受权威；不以概念图、截图、命令 ACK 或组件测试替代同会话验收。
- 不伪造未绑定的执行路线，不把直线连点当规划路径，不在人工释放控制后自动恢复运动。
