# 对话上下文压缩

实现范围：跨轮的自动摘要、近期原文、持久检查点、原文读回和失败恢复。
这是对 Hermes 固定版本相关能力的本地适配，不是完整 ContextCompressor 的原样移植。

## 文件归属

| 文件 | 职责 |
| --- | --- |
| `src/decision/context/compression.py` | 触发、选择旧回合、分批摘要、验证输出、提交检查点及进度 |
| `src/decision/context/transcript.py` | 文本视图、附件省略标识、原文恢复工具定义 |
| `src/decision/tasks/conversation.py` | 原始会话、摘要检查点与读回查询的 SQLite 持久化 |
| `src/decision/tasks/sdk_agent.py` | 复用现有模型连接、SDK 调用和取消；摘要不注册工具 |
| `src/decision/modules/agent_planner.py` | 调用上下文准备、接入原文工具和既有对话事件 |

## 运行过程

1. 每轮先读取已有摘要和摘要之后的原文，短对话不调用摘要模型。
2. 历史文本加当前说明、消息、工具定义达到 48000 字符时，尝试整理旧回合。
   这是本地文本预算，不是 token 数，也不宣称等于提供商窗口上限。
3. 保留最近四轮原文，且不越过执行中／排队／待确认回合。工具调用与结果保持整轮完整。
4. 旧记录按 24000 字符分页送入无工具的摘要请求，同一选定模型逐页合并，并沿用本轮选定的思考强度；摘要最多 6000 字符。
   保留目标、决定、事实、未决问题和不确定性。总结失败、格式错误、超时或未缩短输入时不提交。
5. 全部分页完成后，在事务中复核当前回合仍运行、旧摘要位置未改变、覆盖范围没有未完成回合，才保存检查点。
6. 以摘要加近期原文执行本轮正常对话。SDK 返回中只存本轮增量，摘要不会重复塞进原始历史。

原始消息与附件不被删除或覆盖。取消会终止摘要请求；之前成功的检查点继续有效。
本轮摘要失败会报告失败并使用原有上下文继续；如果原上下文本身超出提供商窗口，正常模型调用仍可能失败。
不自动重放可能已有副作用的工具链来掩盖这种错误。

摘要总时限 120 秒，额外发生模型调用和费用；本功能目标是减少后续上下文，不能保证触发压缩的当轮更快。
常量由 `compression.py` 单点定义，不进入导航配置。尚未按不同提供商 token 窗口调度。

## 信息恢复与权限

- `search_conversation_history(query)`：查找本会话原始消息与工具记录，返回回合 ID 和片段。
- `read_conversation_turn(turn_id, offset)`：按页读回原文与工具证据；`next_offset` 表示还有下一页。
- 只允许读取当前会话。取消／中断时即使没有 SDK 重放内容，已存的工具回执仍参与恢复。
- 编码图片、点云和传感器数组不喂给文本摘要。必须重新打开原始附件／观测工具才能检查其内容。
- 旧批准、摘要、技能摘要都不能授权新动作。状态和运动结果仍从实际执行模块读取，技能详情须重新加载。
- 摘要可能丢失细节或误概括；结构校验不是事实正确性证明。关键事实需读回原文核验。
