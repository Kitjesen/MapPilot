## 速度结论的规则

先量首字、模型响应轮数、工具耗时、上下文整理和总耗时。`model_metrics.elapsed_ms` 是 SDK
整轮时间，包含工具／确认等待，不是纯模型推理时间；本轮首字计时从 SDK 请求流程开始，
不包含此前的上下文压缩。完整端到端仍看会话 started_at/finished_at 和压缩事件。
token 使用提供商返回值，不能用字符估计伪装成实际 token，也不等于已经按 token 调度压缩。
当前主回合字段不合并摘要请求和子助手用量；取消或提供商不返回 usage 时也可能不完整，不能作为精确账单。

本轮同输入对照中 default 摘要在 41.03 秒后因非 JSON 输出失败、没有提交检查点；low
在 47.38 秒完成三页摘要并保留指定地图／巡检点／坐标。不能用失败与成功样本计算加速比。
此前一次成功 default 为 68 秒，但不是同次交错多样本基准，也不能宣称稳定提升百分比。
本轮已修复强度选择不一致，并增加可复测记录；进一步性能结论需要重复测量。

后续源去重将相同历史从 3 页减少到 2 页。一次真实回复返回完整 JSON 代码块而被拒绝，
已通过保留的模型原文定位并修复精确代码块包装解析；原失败证据保留。
最终 low＋去重＋格式修复在 41.26 秒完成，历史上下文 47693→20155 字符，指定事实保留。
这仍是单次观测，不声称稳定加速比例。原始结果见
`artifacts/context-verification/reasoning-comparison.json` 和 `reasoning-model-outputs-final.json`。

启用 Kimi 流式 usage 返回后，一次真实简短答复报告 108 输入／46 输出 token，首字 20719 ms，
SDK 整轮 20890 ms；没有把未返回用量估计为零。见 `real-usage-probe.json`。
